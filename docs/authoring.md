# Как устроены скилы rxops

Скил — папка с инструкцией для ИИ-агента: что проверять на серверах Directum RX, какими командами, что считать нормой и что делать дальше. Агент читает описание всех скилов, а полный текст подгружает, только когда тема совпала с вопросом. Формат открытый (Agent Skills, файл SKILL.md), основной клиент — Claude Code.

## Раскладка

```
skills/<имя>/SKILL.md                инструкция, до 300 строк
skills/<имя>/references/*.md         подробности, агент читает по ссылке из SKILL.md
skills/<имя>/scripts/*               проверки только на чтение
skills/<имя>/scripts/mask_secrets.py копия shared/mask_secrets.py, руками не править
tests/test_<имя>_*.py                тесты скриптов, без сети и без живой RX
```

Справочник ошибок для `rx-logs` собирается из статей сайта: `python3 tools/sync_errors.py` (проверка свежести: `--check`, нужен рядом каталог `../landing`).

После создания папки скила выполните `python3 tools/sync_shared.py`: он положит маскировщик в `scripts/`. Проверка оформления: `python3 tools/check_skills.py <имя>`, тесты: `python3 -m unittest discover -s tests`.

## Фронт-маттер

Только пять ключей. Остальные Claude Code понимает, но claude.ai и Skills API на них падают.

```yaml
---
name: rx-postgresql
description: >-
  Проверка PostgreSQL под Directum RX: ... Использовать, когда ...
license: Apache-2.0
compatibility: Linux-серверы Directum RX 4.x–26.x, PostgreSQL 13–17; нужны psql и python3 3.6+.
metadata:
  author: drxinfra
  version: "0.1.0"
---
```

- `name`: `rx-<тема>`, латиница, цифры и дефис, совпадает с именем папки.
- `description`: до 1024 символов, по-русски. Первая фраза — что делает скил. Дальше «Использовать, когда…» со словами пользователей («база тормозит», «диск кончается»), дословными текстами ошибок и английскими терминами (WAL, autovacuum, OOMKilled). Последняя фраза — чего скил не делает и какой скил взять вместо него. По описанию агент решает, подгружать ли скил, поэтому оно важнее всего остального текста.
- `compatibility`: до 500 символов: где работает и что нужно на машине.

## Тело SKILL.md

1. Заголовок и две-три строки: о чём скил и чем он не занимается.
2. Раздел «Правила» — общий блок ниже, дословно.
3. «Порядок работы»: нумерованные шаги. В каждом: что смотрим, команда, что считается нормой, куда идти при отклонении. Сначала самое быстрое и самое частое.
4. «Что сказать пользователю»: формат итога — что нашли, насколько срочно, что сделать, чем это подтверждено.
5. «Справочник»: какие файлы из `references/` читать и когда, ссылки на статьи drxinfra.ru.

Общий блок «Правила» (вставлять в каждый скил без изменений):

```markdown
## Правила

- Сначала только смотрим. Команду, которая что-то меняет (перезапуск, удаление, изменение настроек, запись в базу, очистку очереди), сначала покажите пользователю, объясните, что она сделает и как это откатить, и выполняйте только после явного согласия.
- Пароли, токены и ключи не выводите. Конфиги и вывод, где они могут быть, читайте через маскировщик: `python3 ${CLAUDE_SKILL_DIR}/scripts/mask_secrets.py ФАЙЛ` или `КОМАНДА 2>&1 | python3 ${CLAUDE_SKILL_DIR}/scripts/mask_secrets.py`.
- Если подключён rxmcp (есть инструменты `rx_help_search` и `rx_help_topic`), поведение Directum RX сверяйте со справкой той версии, что стоит у пользователя, и называйте статью.
- Чего не знаете точно, так и говорите и предлагайте проверить на тестовом стенде. Не придумывайте параметры, пути и имена служб.
- `${CLAUDE_SKILL_DIR}` — папка этого скила. Если агент не подставляет переменную, скрипты лежат в `scripts/` рядом с этим файлом.
```

Ссылки на другие скилы пишите по имени: «дальше скил `rx-rabbitmq`».

## Скрипты

- Только чтение. Ничего не перезапускают, не удаляют и не меняют. Если исправление нужно, оно описывается в тексте отдельной командой с предупреждением, а не выполняется скриптом.
- Python 3.6+ и только стандартная библиотека: в закрытых контурах на Astra Linux и РЕД ОС ставить пакеты обычно нельзя. Shell — bash 4, без экзотики.
- Пароли берутся из файлов, которые пользователь заполнил сам (`~/.netrc`, `~/.pgpass`, права 600), или из переменных окружения, заданных до запуска агента; в вывод не попадают. Не предлагайте агенту `read -s`: его командный инструмент не интерактивный, команда повиснет. Вывод, где они возможны, идёт через `mask_secrets.py`.
- Вывод с кириллицей пишите байтами UTF-8 (`sys.stdout.buffer.write(text.encode("utf-8"))`): в Python 3.6 при `LANG=C` обычный `print` падает на русских буквах.
- У каждого скрипта есть `--help`. Код возврата: 0 норма, 1 найдено отклонение, 2 не удалось проверить.
- Тесты в `tests/` без сети и без живой RX. Запросы к настоящим PostgreSQL, RabbitMQ и Elasticsearch проверяйте вручную в контейнере и удаляйте контейнеры после проверки.

## Откуда брать знания

- Статьи блога и справочник ошибок drxinfra.ru: ссылка на страницу и пересказ своими словами, без копирования целых статей.
- Справка Directum RX: ссылкой на раздел и своими словами. Где поведение зависит от версии, отправляйте агента в справку своей версии через rxmcp.
- Документация PostgreSQL, RabbitMQ, Elasticsearch, Kubernetes, Linux.
- Ничего из закрытых проектов и ничего о конкретных заказчиках: ни имён, ни адресов, ни внутренних названий. `tools/check_skills.py` ловит часть таких упоминаний, остальное на совести автора.

## Язык

Русский, простыми фразами, по делу. Команды и тексты ошибок дословно. Тире в прозе не ставим, как и на сайте.
