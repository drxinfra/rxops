# Как читать отчёт rxdoctor

rxdoctor это бесплатная утилита drxinfra для экспресс-проверки инфраструктуры Directum RX
(https://drxinfra.ru/rxdoctor.html, пример отчёта https://drxinfra.ru/rxdoctor-sample-report.html).
Один файл без установки, только читает: в PostgreSQL сессия только для чтения и фиксированный
список запросов к служебным представлениям, к брокеру, поиску и Kubernetes только запросы на чтение,
на сервере фиксированный список команд. В интернет не ходит. Прогон около 30 секунд.

Скачивать и запускать её на рабочем сервере решает администратор. Если он хочет сначала показать
службе ИБ, что именно выполнится: `rxdoctor explain` печатает все запросы и команды и выходит.

## Запуск

```bash
chmod +x rxdoctor-<версия>-linux-amd64
sudo ./rxdoctor-<версия>-linux-amd64        # первый запуск спросит адреса и учётки, любой пункт можно пропустить
./rxdoctor diff вчера.json сегодня.json     # что изменилось между двумя отчётами
```

Запускают там, где база и брокер уже доступны: на сервере приложений или СУБД. Контейнеры утилита
видит под root или пользователем из группы docker. Отчёт появляется в той же папке в трёх видах:
страница, текст и JSON для сравнения. Ключ `--anonymize` скрывает адреса.

## Как читать

1. Шапка: сколько пунктов в состоянии проблема, внимание, норма и не проверялось.
2. «Сначала главное»: все красные (проблема) и жёлтые (внимание) пункты одним списком. Компонент,
   который не ответил, стоит красной строкой в начале. С этого списка и начинайте.
3. Разделы по источникам. У каждого пункта код, состояние, одна строка итога, «Чем грозит»,
   «Что делать» и подробности (номера сессий, имена очередей, контейнеров).

а не из памяти.

## Как связать с разбором

- Красный пункт в разделе базы, брокера или поиска: передайте в скил компонента вместе с подробностями
  из отчёта.
- OS-06 и OS-07 вместе (убит по памяти и близко к лимиту): сначала лимит и память сервиса,
  потом утечка. Два отчёта с разницей в сутки через `rxdoctor diff` показывают, что только растёт.
- ES-07 после OS-01 (диск кончился): освобождают место, потом снимают блокировку индексов, потом
  проверяют очередь индексации (MQ-08). Порядок важен, и каждое действие с согласия пользователя.
