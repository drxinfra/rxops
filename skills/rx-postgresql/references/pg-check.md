# pg_check.py: что смотрит, пороги, права

Скрипт только читает. Каждый запрос идёт отдельным вызовом `psql` в сессии с `default_transaction_read_only = on`, `statement_timeout = 10s` (ключ `--timeout`), `lock_timeout = 1s` и именем приложения `rxops-pg_check`. Ошибка одного запроса (например, нет прав) превращает в SKIP только свою проверку. Данные таблиц RX скрипт не читает: только системные представления и статистику.

## Как подключаться

| Где база | Команда |
|---|---|
| сервер базы, unix-сокет | `sudo -u postgres python3 pg_check.py -d <база RX>` |
| по сети | `python3 pg_check.py -d "host=<сервер> port=5432 dbname=<база RX> user=<роль>"` |
| контейнер Docker | `python3 pg_check.py --psql-cmd "docker exec -i <контейнер> psql -U postgres" -d <база RX>` |
| под в Kubernetes | `python3 pg_check.py --psql-cmd "kubectl exec -i -n <ns> <под> -- psql -U postgres" -d <база RX>` |

- Пароль: `~/.pgpass` (права `0600`) или переменная `PGPASSWORD`, их задаёт пользователь. Скрипт вызывает `psql -w` и пароль не спрашивает.
- Подключайтесь к PostgreSQL напрямую. Через PgBouncer в режиме transaction часть данных о сессиях теряет смысл.
- Если база отвечает `too many clients already` или `remaining connection slots are reserved`, подключайтесь суперпользователем: для него оставлены места `superuser_reserved_connections`. Скрипт берёт одно соединение за раз.
- Проверки диска и памяти (`disk`) работают, только когда скрипт запущен на сервере базы без `--psql-cmd`: каталог данных сверяется с `postmaster.pid`, чтобы не показать место чужого экземпляра.

## Права

Полную картину дают суперпользователь или роль с `pg_monitor`. Без неё (проверено на PostgreSQL 16) у чужих сессий не видны состояние, время транзакции и текст запроса, не читаются `pg_ls_waldir()`, `pg_ls_archive_statusdir()`, `data_directory` и `shared_preload_libraries`. Скрипт в таком случае пишет «чужие сессии не видны без роли pg_monitor». Ожидания блокировок он берёт из `pg_locks`, они видны всем.

Отдельная роль для регулярных запусков. Создание роли меняет базу: только с согласия, пароль задаёт пользователь сам.

```sql
CREATE ROLE rx_monitor LOGIN IN ROLE pg_monitor;
\password rx_monitor
```

В `pg_hba.conf` строка для адреса, откуда запускаете, затем `SELECT pg_reload_conf();`. Так же устроен пользователь мониторинга в решении «Мониторинг Directum RX» (справка RX: monitoring_nastroyka_postgresql.htm, роль с `pg_monitor`).

## Проверки и пороги

Пороги стартовые. Их подстраивают под фон своей системы: `--list-thresholds` показывает все, `--threshold ИМЯ=ЗНАЧЕНИЕ` меняет.

| Ключ | Что смотрит | WARN | CRIT |
|---|---|---|---|
| `server` | роль (ведущий или реплика), время работы, есть ли в базе таблицы `sungero_*`, права | не база RX | |
| `version` | мажорная версия и конец её поддержки сообществом | версия без поддержки | |
| `connections` | `pg_stat_activity` по приложениям и состояниям против `max_connections` и мест для обычных ролей | 80 % | 95 % |
| `long_xact` | транзакции дольше порога, подготовленные транзакции (2PC) | 5 мин, 2PC от 5 мин | 30 мин |
| `idle_in_xact` | `idle in transaction` по времени молчания | 5 мин | 30 мин |
| `locks` | ожидающие из `pg_locks`, `pg_blocking_pids`, корень цепочки, `AccessExclusiveLock` у корня | ожидание 30 с | 5 мин |
| `deadlocks` | `pg_stat_database.deadlocks`, в сутки и за окно | 10 в сутки или новые за окно | 100 в сутки |
| `wal` | размер `pg_wal` против `max_wal_size + wal_keep_size`, запись WAL за окно | в 2 раза | в 5 раз |
| `archiver` | `pg_stat_archiver`, очередь `.ready`, пустой `archive_command` | очередь от 10 | падает сейчас, очередь от 100 |
| `slots` | `pg_replication_slots`: активность, удерживаемый WAL, `wal_status` | неактивен или от 1 ГБ | от 10 ГБ, `lost`, `unreserved` |
| `replication` | на ведущем `pg_stat_replication` в байтах; на реплике приём и применение | от 1 ГБ, не streaming | от 10 ГБ |
| `disk` | свободное место и иноды разделов данных, pg_wal, табличных пространств; `secdel`; память | меньше 20 % | меньше 10 % |
| `autovacuum` | мёртвые строки, давность vacuum, выключенный autovacuum | 20 % от 100 тыс. строк | 50 % у таблицы от 1 ГБ, autovacuum off |
| `wraparound` | `age(datfrozenxid)`, `mxid_age`, кто держит горизонт | 1 млрд | 1,5 млрд |
| `checkpoints` | доля вынужденных чекпоинтов | больше 50 % | |
| `cache` | попадание в кэш за окно и накопительно, временные файлы | ниже 95 % при 10 тыс. блоков с диска | |
| `statements` | `pg_stat_statements`: по суммарному времени, вызовам, чтению | | |
| `tls` | `pg_stat_ssl`: соединения по сети без шифрования | | |
| `settings` | `fsync`, `full_page_writes`, значения по умолчанию, `max_prepared_transactions` против `max_connections` (по справке RX они равны), ожидающие перезапуска, ошибки файлов конфигурации и `pg_hba.conf`, ёмкость таблицы блокировок | значение по умолчанию у ключевых, `max_prepared_transactions` меньше `max_connections` | `fsync` или `full_page_writes` выключены |
| `sizes` | размеры баз и крупнейших таблиц | | |

Ограничения, о которых стоит сказать пользователю:

- Окно замера 10 с: для кэша и записи WAL это мгновенный снимок. Для расчёта места под архив WAL меряют разницу `pg_current_wal_lsn()` за час рабочего дня.
- Частота дедлоков при статистике моложе суток считается как за сутки.
- На реплике autovacuum и чекпоинты не оцениваются, смотрите ведущий сервер.
- Журнал PostgreSQL скрипт не читает: команды поиска есть в SKILL.md, шаг 14.

## Вывод

Текст: строка на проверку `[OK]`, `[INFO]`, `[WARN]`, `[CRIT]`, `[SKIP]` и детали под ней; в начале раздел «Главное» с CRIT и WARN. `--json`: поля `server`, `checks` (у каждой `key`, `status`, `summary`, `details`, `data`), `summary`, `exit_code`. JSON удобно сохранять и сравнивать между запусками. Код возврата: 0 норма, 1 есть WARN или CRIT, 2 не удалось подключиться.

## Ручной SQL

`scripts/pg_check.sql` содержит те же запросы для psql: `psql -X -d <база RX> -f pg_check.sql`. Файл генерируется из скрипта (`pg_check.py --print-sql`), руками его не правят. Версии PostgreSQL 13-17 и роль сервера разводятся командами `\if`. В DBeaver и pgAdmin выполняйте запросы по одному и пропускайте строки с обратной косой чертой.
