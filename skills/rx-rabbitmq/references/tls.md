# RabbitMQ для RX по TLS

Пересказ статьи drxinfra.ru «RabbitMQ для Directum RX по TLS: перевод без простоя»
(https://drxinfra.ru/blog/rx-rabbitmq-tls-no-downtime.html). Все шаги, кроме проверок, меняют систему и
выполняются только с согласия.

## Идея

Брокер умеет слушать обычный порт 5672 и порт с TLS 5671 одновременно. Поэтому переходят по частям:
включают 5671 рядом с 5672, переводят клиентов по одному (откат: вернуть клиенту прежний порт), а 5672
закрывают, когда на нём никого не осталось хотя бы сутки, чтобы попались ночные задания и редкие
выгрузки. Закрыть 5672 первым значит уронить всех, кто не успел перейти.

## Проверки до работ

```bash
openssl x509 -in server.crt -noout -subject -ext subjectAltName -enddate
openssl x509 -in server.crt -noout -pubkey | sha256sum
openssl pkey -in server.key -pubout | sha256sum          # суммы должны совпасть
grep -c 'BEGIN CERTIFICATE' server.crt; grep -c 'END CERTIFICATE' server.crt
rabbitmqctl list_connections user peer_host ssl | sort | uniq -c
```

- В SAN все имена, по которым к брокеру подключаются клиенты (для кластера каждое имя узла и общее имя).
- Файл сертификата содержит сертификат и промежуточные по порядку, ключ читается пользователем брокера.
- Список соединений даёт всех клиентов: RX, Ario, мониторинг, скрипты. Непонятный адрес уточняют по
  колонке `client_properties`. Тот же список показывает `mq_check.py`, а с ключом `--expect-tls` он
  выводит клиентов без TLS как отклонение.

## Брокер

Фрагмент rabbitmq.conf из статьи: оба слушателя, сертификаты, TLS 1.2 и 1.3. `verify_none` здесь значит,
что брокер не требует сертификата от клиента; клиент входит по паролю и сам проверяет сертификат брокера.

```ini
listeners.tcp.default = 5672
listeners.ssl.default = 5671
ssl_options.cacertfile = /etc/rabbitmq/tls/ca.crt
ssl_options.certfile   = /etc/rabbitmq/tls/server.crt
ssl_options.keyfile    = /etc/rabbitmq/tls/server.key
ssl_options.verify     = verify_none
ssl_options.fail_if_no_peer_cert = false
ssl_options.versions.1 = tlsv1.3
ssl_options.versions.2 = tlsv1.2
```

Новые слушатели появляются после перезапуска узла, в кластере узлы перезапускают по одному. Проверка:
`rabbitmq-diagnostics listeners` (должны быть 5672 и 5671) и
`openssl s_client -connect <брокер>:5671 -servername <брокер> </dev/null | head -20`.

## Клиенты RX

В настройках подключения RX к брокеру включают признак TLS и порт 5671, а корень удостоверяющего центра
добавляют в доверенные внутри контейнеров сервисов: хранилище сертификатов хоста контейнерам не видно.
Сам сервис RX в тексте ошибки называет настройку `useTls`; в справке 25.2 её описания нет, поэтому
точное имя и место параметра сверьте со справкой своей версии и на тестовом стенде. После перезапуска
сервисов у их соединений должно стать `ssl = true`:
`rabbitmqctl list_connections user peer_host ssl ssl_protocol`.

Когда список без TLS пуст сутки, обычный слушатель закрывают (`listeners.tcp = none`) и снова
перезапускают узлы по одному. Отдельно настраиваются панель управления (`management.ssl.*`, порт 15671),
порт метрик 15692 (доступ закрыть сетью) и обмен между узлами кластера (обычно закрывают сетью, TLS для
него требует отдельной репетиции).

## Продление сертификата

RabbitMQ кэширует прочитанные сертификаты: после замены файлов новые соединения какое-то время получают
старый. Кэш сбрасывают на каждом узле без перезапуска: `rabbitmqctl eval 'ssl:clear_pem_cache().'`, потом
`openssl s_client` должен показать новый срок. Срок сертификата брокера держите под наблюдением.

## Ошибки

| Где и что | Причина |
|---|---|
| RX: `check useTls setting. Incorrect port` | признак TLS и порт не совпадают с брокером или брокер недоступен |
| RX: `RemoteCertificateNameMismatch` | имени, по которому подключается RX, нет в SAN сертификата брокера |
| RX: `UntrustedRoot` или `PartialChain` | корень не доверен в контейнере или брокер не отдаёт промежуточный сертификат |
| брокер: `CLIENT ALERT: Fatal - Certificate Unknown` | клиент не принял сертификат брокера, искать на стороне клиента |
| брокер: ошибка рукопожатия на 5671 | клиент пришёл на TLS-порт обычным AMQP |
| брокер не слушает 5671 после перезапуска | не читается ключ или сертификат: права, путь, формат; причина в журнале узла при старте |
| брокер: `ACCESS_REFUSED` | TLS ни при чём: неверный логин или пароль |

Не отключайте на клиентах проверку сертификата брокера, чтобы «заработало»: шифрование без проверки не
защищает от подмены брокера.
