# Справочник известных ошибок и как его читает match_errors.py

## Откуда база

`scripts/known_errors.json` собирается из исходников справочника https://drxinfra.ru/errors/
скриптом `tools/sync_errors.py` репозитория rxops. В каждой записи: дословный текст ошибки
(`title`), что это значит одной фразой (`what`), компонент, шаблоны поиска, ссылка на страницу
разбора и шаги «Как проверить» и «Что сделать». Полный разбор, причины и примеры только на сайте:
ссылку давайте пользователю, текст страницы не пересказывайте целиком.

Новые ошибки появляются на сайте раньше, чем в скиле. Если строки нет в базе, её можно вставить
в поле поиска на странице справочника; если и там нет, пользователь может прислать её через контакты
на drxinfra.ru, чтобы её разобрали и добавили.

## Как считается совпадение

- Шаблоны те же, что у поиска на сайте: регулярные выражения без учёта регистра.
- Запись JSON разбирается: шаблоны проверяются и по сырой строке, и по полям записи, каждое поле
  отдельной строкой (`mt` с подставленными `args`, `ex.type: ex.m`, стек и остальные текстовые поля).
  Так находятся тексты, которые в сыром JSON экранированы (`\"`, `с`), и работают шаблоны
  с `^` и `$`.
- В обычной строке шаблон проверяется ещё и по тексту без начального времени и уровня.
- Если строка подходит под несколько ошибок, она засчитывается той, у которой совпадение длиннее.
  При равной длине выигрывает ошибка, у которой совпало больше шаблонов, затем та, чей заголовок
  больше похож на строку. Остальные показаны в «также подходит» со счётчиком.
- Быстрый отсев по обязательным подстрокам шаблонов не теряет совпадений: это проверяет тест
  `tests/test_rx_logs_match.py` на всех текстах базы.

## Поправки для журналов целиком

Поиск на сайте рассчитан на одну строку, которую человек сам выбрал. В журнале на миллион строк
часть шаблонов шумит, поэтому скрипт добавляет две оговорки:

- голый код SQLSTATE (`\b57014\b`, `40P01`) засчитывается, только если после кода стоит двоеточие
  или в строке есть признак PostgreSQL (`SqlState`, `Npgsql`, `postgres`): иначе совпадают номера
  документов и длительности;
- имя проверки работоспособности (`INDEXING_SERVICE`, `PREVIEW_STORAGE`) со статусом `healthy`
  рядом не считается ошибкой: так выглядят штатные записи о состоянии раз в 30 минут.

## Где возможна ошибка

- Широкие шаблоны вроде `unassigned shards`, `HTTP 500`, `Internal Server Error` находят и записи,
  где это упоминается мимоходом. Смотрите пример строки и счётчик.
- Время без часового пояса скрипт считает местным временем машины, где он запущен. Если журналы
  скопированы с сервера в другом поясе или контейнер пишет в UTC без пометки, окно `--since`
  и `--until` сдвинется. Проверьте пояс по одной известной записи.
- Строки стека без своего времени получают время первой строки записи. Строки до первой метки
  времени в файле остаются без времени, окно к ним не применяется, скрипт пишет, сколько их.
- База знает инфраструктурные ошибки и ошибки платформы. Ошибки прикладной разработки заказчика
  в ней не описаны: для них нужен журнал, трасса и разработчик.
- У части записей сайта заголовок пересказывает ошибку («column ... does not exist») и сам
  не совпадает со своими шаблонами. На поиск по настоящим строкам это не влияет.

## Ключи, которые чаще всего нужны

```bash
python3 match_errors.py <LOGS_PATH> --since 10:00 --until 10:30          # окно сегодня
python3 match_errors.py <LOGS_PATH> --since 2h --sort time --details     # что появилось первым
python3 match_errors.py <файл> --json                                    # для разбора скриптом
python3 match_errors.py --help                                           # все ключи и правила
```
