# Версии Directum RX и пути обновления

Источники: статья drxinfra «Версия Directum RX и платформы Sungero»
(https://drxinfra.ru/blog/rx-version-platform-solution.html) и справка Directum RX 25.2, статьи
`admin_obnovlenie_sistemy_linux.htm`, `admin_podgotovka_k_obnovl_linux.htm`,
`inst_rx_251_252_linux.htm`, `upd_rezhim_teh_obsluzhivaniya_lin.htm`. Для другой целевой версии
откройте те же разделы в справке этой версии: пути и особенности меняются от выпуска к выпуску.

## Две версии, а не одна

- **Платформа** (Sungero): сервер приложений, сервисы, веб-клиент. Номер вида `25.2.0.0071`.
- **Прикладная разработка**: модули и логика, плюс доработки внедрения. Номер стандартной
  прикладной разработки вида `25.2.0.40`.

Первые две цифры общие и обозначают выпуск (25.2). Внутри выпуска выходят обновления с
исправлениями, поэтому «у нас 25.2» не версия. Свои номера есть у веб-агента, Directum Launcher и
мобильных приложений; у заказного решения может быть своя версия или дата последней публикации.

Где посмотреть:

1. Веб-клиент: меню пользователя справа вверху, «О программе». Заголовок справки показывает
   только выпуск.
2. Сервер: Directum Launcher показывает установленные компоненты с версиями
   (`./do.sh components list` выводит их таблицей). В контейнерах номер обычно стоит в тегах
   образов, их показывает `preflight.py` в строке «Образы в работе».
3. Справка «Что нового»: таблица «Версии компонентов» для каждого обновления. По ней видно, к
   какому обновлению относится ваша пара номеров.

Вендору и интегратору называйте обе версии, а при доработках и их версию. Записывайте версии
в паспорт стенда после каждого обновления.

## Пути обновления до 25.2

По справке 25.2 (`admin_obnovlenie_sistemy_linux.htm`): напрямую обновление поддерживается с трёх
последних вышедших версий, то есть до 25.2 с 4.11, 4.12 и 25.1. Обновление до 25.2 вообще
поддерживается с 4.6 и выше; с более ранних версий идут поэтапно:

| Текущая версия | Шаги |
|---|---|
| 4.6 | 4.6 → 4.9 → 4.12 → 25.2 |
| 4.7 | 4.7 → 4.10 → 25.1 → 25.2 |
| 4.8 | 4.8 → 4.11 → 25.2 |
| 4.9 | 4.9 → 4.12 → 25.2 |
| 4.10 | 4.10 → 25.1 → 25.2 |
| 4.11, 4.12, 25.1 | сразу 25.2 |

Каждый шаг: свой дистрибутив, своя конвертация базы, своя статья «Обновление с версии X на Y».
Время каждого шага замеряют на репетиции. Порядок по справке: обновить тестовый контур,
протестировать (задачи на согласование по регламенту, создание и регистрация документов),
оформить протокол, потом рабочий контур.

## Что важно знать о версиях

- **Заказная разработка.** Перед обновлением запросите у поставщика пакет разработки под нужную
  версию. Пакет собирают на новой версии; при обновлении указывают все пакеты, установленные на
  сервере, за один раз, иначе работа веб-сервера нарушится.
- **4.7: идентификаторы int → long.** При обновлении на 4.7 нужен запас места на диске, равный
  размеру базы; после конвертации база вырастает примерно на 30 %. Модифицированную разработку
  адаптируют под большие ИД до обновления с 4.6.
- **4.6 и ниже → 4.7 и выше.** После обновления справка требует сконвертировать типы полей и
  восстановить внешние ключи (`--fix-navigation-columns-type`, `--restore-fk`, см.
  `references/commands.md`); ключ, который не восстановился, пишется как `'<Колонка>' - FAILED`.
- **4.9.** Режим технического обслуживания через Directum Launcher доступен с 4.9 (через обложку
  «Администрирование» с 4.8). Настройки процессов по умолчанию с 4.9 нельзя строить на сущностях
  без внешних ссылок.
- **4.12.** Управление фоновыми активностями (безопасный режим) доступно с 4.12.
- **Ниже 4.10 и с 4.10.** Скрипт обновления через командную строку генерируется по-разному:
  `create-update-script` до 4.10, `update` с 4.10 (`references/commands.md`).
- **25.1: компонент directumrx переименован в base.** Папка `etc/_builds/directumrx` при
  обновлении удаляется, архив `directumrx.tar.gz` (или `.zip`) в корне папки надо убрать до
  начала, иначе «root action ... already exists».
- **Путь к Directum Launcher.** Для обновления общий путь к файлам не длиннее 256 символов, без
  пробелов, кириллицы, запятых и спецсимволов, например `/srv/DirectumLauncher`.
- **Папка Directum Launcher перезаписывается.** Скрипт обновления удаляет в ней всё, кроме `etc`
  и `log`: сертификаты для HTTPS и подписания там держать нельзя.

## Требования к окружению

Версии ОС, PostgreSQL или MS SQL, RabbitMQ, Elasticsearch, .NET и браузеров перечислены в документе
вендора «Directum RX <версия>. Типовые требования к аппаратному и программному обеспечению». Справка
на него ссылается, но сами версии в ней не перечислены. Не называйте поддерживаемые версии по
памяти: попросите у пользователя документ его целевой версии или ссылку на него.

## Веб-агент WebAccessAgent

Нумерация своя и не совпадает с RX: в обновлении 25.2.0.37 агент 6.0.3.1002, в 25.2.0.38 и
25.2.0.40 уже 6.0.3.1005 (статья https://drxinfra.ru/blog/rx-webaccessagent.html). Агент
обновляется сам. После обновления сверьте версию в «О программе» агента с таблицей «Версии
компонентов»; если на компьютере старее, автообновление не дошло, агент переустанавливают из меню
пользователя. На терминальном сервере после обновления службы перезапускают все экземпляры агента,
в рабочее время её не обновляют: открытые правки могут не сохраниться.
