# Команды Directum Launcher и DeploymentToolCore для обновления

Всё ниже взято из справки Directum RX 25.2, имя статьи в последнем столбце. Команды выполняются в
папке Directum Launcher: на Linux `./do.sh <команда>`, на Windows `do <команда>`. Полный список и
ключи своей версии: `./do.sh --help` и `./do.sh <команда> --help`. Команд, которых здесь нет, не
придумывайте: открывайте справку своей версии.

Столбец «Меняет»: нет значит только смотрит (по описанию в справке; на новой для себя версии
сначала запустите на тестовом стенде); да значит выполнять только после явного согласия, с
объяснением, что команда сделает и как вернуть.

## Посмотреть состояние

| Команда | Что делает | Меняет | Статья |
|---|---|---|---|
| `./do.sh --help`, `./do.sh <команда> --help` | список команд и ключей | нет | `admin_komandy_skriptov_razvertyvaniia_linux.htm` |
| `./do.sh components list` | компоненты: установленные, добавленные, доступные | нет | там же |
| `./do.sh all check` | проверить работоспособность всех сервисов | нет | там же |
| `./do.sh platform check`, `./do.sh <сервис> check` | работоспособность платформы или сервиса | нет | там же |
| `./do.sh db check` | подключение к базе по CONNECTION_STRING | нет | там же |
| `./do.sh platform get_maintenance_mode_status` | состояние режима технического обслуживания | нет | `upd_rezhim_teh_obsluzhivaniya_lin.htm` |
| `./do.sh dt get_deployed_solutions` | опубликованные решения | нет | `dt_development_deploy_commandline.htm` |

Состояние сервисов видно и в Directum Launcher, режим «Состояние»: общий статус проверок healthy,
degraded или unhealthy, по щелчку текст статус-файла (`admin_status_v_dl_linux.htm`). Статус-файлы
`<компьютер>.<сервис>.status` лежат в подпапке `status` папки журналов и обновляются каждые
10 секунд; файл, который не обновляется, значит, что сервис не работает
(`admin_status_files_and_log_files_linux.htm`). Их читает `preflight.py --status-dir`.

## Закрыть и открыть вход

| Команда | Что делает | Меняет | Статья |
|---|---|---|---|
| `./do.sh platform turn_maintenance_mode_on --message="<текст>"` | режим обслуживания, фоновые активности в безопасный режим, сообщение на странице входа; `--safe-mode=false` без безопасного режима | да | `upd_rezhim_teh_obsluzhivaniya_lin.htm` |
| `./do.sh platform turn_maintenance_mode_off` | выключить режим и безопасный режим | да | там же |
| `./do.sh platform switch_maintenance_mode --message="<текст>"` | включить режим с сообщением; выключать той же командой без ключа | да | там же |

В режиме обслуживания сеансы пользователей завершаются, входят только пользователи роли
«Администраторы». Для включения через Directum Launcher должен работать сервис интеграции.

## Обновление через командную строку (Linux, Docker)

Порядок из статьи `admin_obnovlenie_komand_stroka_linux.htm`. Архивы новой версии сначала кладут
в корень папки Directum Launcher со старой версией.

| Шаг | Команда | Меняет |
|---|---|---|
| остановить и удалить сервисы | `./do.sh all down` | да |
| с версии 4.10 и выше: сгенерировать и выполнить скрипт обновления | `./do.sh update --package="<путь к DirectumLauncher.tar.gz>"` | да |
| ниже 4.10: сгенерировать скрипт и выполнить его | `./do.sh create-update-script --package="<путь>"`, затем `./update.sh` | да |
| добавить компоненты | `./do.sh components add_all` | да |
| установить веб-сервер и сервисы (здесь идёт конвертация базы) | `./do.sh platform install` | да |
| опубликовать стандартную и заказную разработку, импортировать шаблоны | `./do.sh base install --package="<пакет 1>;<пакет 2>"` | да |
| только заказная разработка и свои шаблоны | `./do.sh dt deploy --package="<пакеты через ;>"`, `./do.sh rxcmd import_templates --templates_dir_path="<папка>"` | да |
| обновить справку | `./do.sh webhelp install` | да |

Скрипт обновления удаляет в папке всё, кроме `etc` и `log`, и распаковывает туда новую версию.
В статье команд скриптов развёртывания добавление компонентов записано как `components add_all`,
а в статье об устранении неисправностей как `components add-all`: проверьте написание в
`./do.sh components --help` своей версии.

Только для перехода с 4.6 и ниже на 4.7 и выше:

```bash
./do.sh dt run --command="-n \"Service User\" -p <пароль> --fix-navigation-columns-type"
./do.sh dt run --command="-n \"Service User\" -p <пароль> --restore-fk"
```

затем в базе `vacuum full analyze;` (долго). Эти команды администратор выполняет сам в своём терминале,
не через агента. Пароль в командной строке остаётся в истории оболочки: можно прочитать его в переменную
(`read -rs RXPW`) и подставить `\"$RXPW\"`.

## Обновление через страницу Directum Launcher

`./DirectumLauncher --host=0.0.0.0`, страница открывается на порту 5000 (`--port=<номер>` меняет
порт). Если в `config.yml` есть зашифрованные параметры, перед запуском экспортируют переменную
окружения с паролем шифрования. Дальше переключатель «Обновление», флажок «Платформа Sungero», в
поле «Сервер БД» база прежней версии, «Прикладная разработка базового решения» с путём до пакета,
все пакеты заказной разработки сразу, «Обновить». Ход этапов на странице берётся из
`log/current.log`; при ошибке устранить причину и нажать «Повторить» (`inst_rx_251_252_linux.htm`,
`inst_rx_252_linux.htm`).

## Kubernetes

Статья `admin_upd_kuber.htm`: через Directum Launcher обновляют только компоненты Platform и Base,
в остальных случаях командная строка на узле администрирования:

| Шаг | Команда | Меняет |
|---|---|---|
| добавить компоненты | `./do.sh components add_all` | да |
| конвертация базы | `./do.sh platform k8s_install db_convert` | да |
| применить настройки сервисов | `./do.sh platform k8s_install services-up` | да |
| прикладная разработка и решения | `./do.sh rx install --package-from-component="projectplanning;agile;memo;rxmd"` или `./do.sh rx install` | да |
| шаблоны решений | `./do.sh <решение> import_templates` | да |
| клиентская часть | `./do.sh webclient k8s_copy_all` | да |
| перезапуск сервисов | `./do.sh platform k8s_install services-up` | да |

При обновлении с 4.10 на 4.11 и выше конфигурационный файл приводят к структуре `values.yaml` из
архива Platform новой версии. Как откатить релиз в Kubernetes, справка не описывает: порядок
отката проверьте на тестовом контуре.

## Публикация разработки

`dt_development_deploy_commandline.htm`:

| Команда | Что делает | Меняет |
|---|---|---|
| `./do.sh dt deploy --package="<пакеты через ;>"` | публикация, инициализация, настройки по умолчанию; уже опубликованная версия повторно не публикуется | да |
| `... --force` | публикация принудительно | да |
| `... --init=False` | без инициализации и настроек, например при обновлении внутри версии | да |
| `./do.sh dt merge_packages "<итоговый пакет>" --packages="<пакеты через ;>"` | объединить пакеты заранее, без публикации: окно короче | пишет файл |

Утилиту запускают из папки того Directum Launcher, которым установлена система. Публикация идёт,
только если версии DeploymentToolCore и веб-сервера совпадают до редакции релиза (25.2.0.XXXX).
Коды возврата 1–8: https://drxinfra.ru/errors/deploymenttoolcore-exit-codes.html.

## После обновления: место на диске

Справка советует удалить в `etc/_builds` папки прошлой версии (`DBConverter/<прошлая>`,
`Redist/<прошлая>`, `Encryptor/<прошлая>`, `CertificateTool/<прошлая>`, `PlatformBuilds`, `_cache`)
и старые журналы: `./do.sh clean_logs --config_path="<путь к config.yml>" --skip_last_modified_days="7"`.
Оба действия необратимы. Делайте их после точки невозврата и первых суток, пока откат ещё возможен,
сборки прежней версии лучше не трогать.
