# Проверки после обновления: руками, Playwright, JMeter

Мониторинг сервисов отвечает на вопрос «процессы работают?», пользователю важно «могу ли я
сделать свою работу?». Между ними сертификат, прокси, кэш браузера, прикладная разработка и
права. Поэтому после обновления, кроме `preflight.py --post`, нужна проверка, которая ходит в
систему как пользователь.

Источники: https://drxinfra.ru/blog/playwright-rx-part-1.html,
https://drxinfra.ru/blog/rx-jmeter-load-testing.html, https://drxinfra.ru/blog/rx-update-with-rollback.html;
справка Directum RX 25.2, `admin_obnovlenie_sistemy_linux.htm` (что тестировать на тестовом контуре).

## Минимум руками, пока вход закрыт

В режиме технического обслуживания входят только пользователи роли «Администраторы», поэтому эти
проверки делают под администратором:

1. Веб-клиент открывается тем способом, каким входят пользователи: через тот же адрес, прокси и
   единый вход.
2. «О программе»: новые версии платформы и прикладной разработки.
3. Задание создаётся, отправляется и приходит исполнителю; задача на согласование по регламенту
   уходит.
4. Документ создаётся, регистрируется, открывается; новая версия сохраняется.
5. Поиск находит документ, созданный после обновления.
6. Если есть: интеграции отвечают, письма уходят.
7. Directum Launcher, режим «Состояние»: нет unhealthy; мониторинг видит новую версию.

Результат оформите коротким протоколом: справка просит протокол тестирования после обновления
тестового контура, тот же список годится и для прода.

## Автотест на Playwright

Делает то же за минуту и одинаково каждый раз. Основное из статьи:

- тестовая учётка отдельная, без второго фактора и с минимальными правами, не администратор;
  пароль только в переменной окружения;
- селекторы по ролям и подписям из `npx playwright codegen https://rx.example.com/Client/`, а не по
  CSS-классам: классы веб-клиента меняются с версиями;
- вход один раз (setup-проект сохраняет состояние в `.auth/user.json`), дальше короткие тесты:
  веб-клиент загрузился и показывает список заданий, в консоли браузера нет ошибок;
- `ignoreHTTPSErrors: false`: истёкший сертификат тест должен поймать;
- запуск `RX_URL=https://rx.example.com/Client/ RX_USER=autotest RX_PASSWORD='…' npx playwright test`,
  разбор упавшего шага `npx playwright show-report` (по трассе видно 502 от прокси, 401 от
  поставщика входа).

Под обычной учёткой автотест пройдёт только после выключения режима обслуживания. Если вход нужно
держать закрытым дольше, закройте его другим способом (например, на прокси для всех, кроме сети
тестов) и проверьте этот способ на репетиции.

## Нагрузка: JMeter при новой версии

Нагрузочный тест гоняют только на тестовом контуре, поднятом из бэкапа прода, никогда на проде.

1. Каждый сценарий пройти одним потоком с View Results Tree: красные проверки ответов показывают,
   какие запросы изменились в новой версии.
2. Изменившиеся действия перезаписать заново, а не править руками. Сценарии держат по действиям
   (Transaction Controller на каждое), тогда перезаписывается одно действие.
3. Сравнивать с прошлой версией на том же контуре и профиле: разница между версиями говорит больше,
   чем абсолютные числа.
4. Смотреть 95-й и 99-й перцентили, а не среднее
   (https://drxinfra.ru/blog/rx-percentiles-p90-p95-p99.html). Запуск без интерфейса:
   `jmeter -n -t plan.jmx -l results.jtl -e -o report/`, генератор нагрузки на отдельной машине.

## Первые сутки

Часть проблем видна только под дневной нагрузкой: время ответа в часы пик, рост очередей RabbitMQ,
повторяющиеся ошибки в журналах (скилы `rx-logs`, `rx-rabbitmq`), обращения пользователей. Автотест
полезно оставить запускаться каждое утро.
