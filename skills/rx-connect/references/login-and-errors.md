# rxmcp: вход, настройки, ошибки

## Способы входа

| Способ | Когда подходит | Что делает пользователь |
|---|---|---|
| `password` | в RX включён вход по паролю | `rxmcp setup`, пароль вводится один раз |
| `cookie` + `--sso` | вход через Keycloak или другой OIDC-провайдер | один раз `rxmcp login --sso`: дальше rxmcp сам получает новую cookie RX, пока жива сессия провайдера |
| `cookie` | работает всегда, в том числе с доменом и SSO | войти в RX в браузере, скопировать cookie `sungero_client`, выполнить `rxmcp login --paste` |
| `oidc` | у провайдера заведён клиент для rxmcp | `rxmcp login`, вход в браузере или по коду устройства |
| `bearer` | токен уже есть | `RXMCP_TOKEN=…` в профиле или окружении |

Сессия провайдера (`--sso`) открывает вход во все приложения этого провайдера, а не только в RX: она хранится с правами `0600` и удаляется командой `rxmcp logout`. Если RX требует второй фактор, вход `--sso` не пройдёт, остаётся cookie вручную.

## Где лежат настройки

- Профиль: `~/.config/rxmcp/config.json` (Windows: `%AppData%\rxmcp\config.json`), права `0600`.
- В конфиге ИИ-клиента только путь к бинарнику, без секретов.
- `rxmcp config` показывает настройки без секретов, `rxmcp config set ИМЯ=значение` меняет, `rxmcp help` перечисляет все переменные.
- Вторая система (тестовый стенд): `RXMCP_HOME=~/.config/rxmcp-test rxmcp setup`, сервер появится в клиенте под своим именем.
- Секреты в связке ключей ОС: `rxmcp secrets keyring`, обратно в файлы: `rxmcp secrets file`. На сервере Linux без графического сеанса связки нет.

## Ошибки подключения

| Симптом | Причина | Что делать |
|---|---|---|
| `401`, «RX отклонил учётку» | истекла cookie или сессия провайдера, неверный пароль | `rxmcp login --sso` или `rxmcp login --paste`; для пароля `rxmcp setup` |
| «новую куку получить не удалось» | у провайдера кончилась сессия | войти в RX в браузере, затем `rxmcp login --sso` |
| `x509: certificate signed by unknown authority` | сертификат RX выпущен внутренним УЦ | `rxmcp config set RXMCP_CA=/путь/к/корневому.pem` |
| `$metadata` отдаёт 404 | сервис интеграции не опубликован на этом адресе | уточнить адрес у администратора веб-сервера; адрес вида `https://сервер/Integration/odata` |
| `$metadata` отдаёт 403 | возможно, у пользователя нет доступа к сервису интеграции | проверить роль «Пользователи сервиса интеграции»: по справке в ней по умолчанию все пользователи |
| справка не находится | индекс ещё качается или справка лежит по нестандартному адресу | `rxmcp docs status`; адрес задаётся `RXMCP_HELP_URL` |
| инструментов `rx_*` нет | клиент не перезапущен, сервер прописан в другой клиент | перезапустить клиент; `rxmcp setup` ещё раз |

## Что видит провайдер модели

Всё, что rxmcp прочитал и вернул агенту, уходит провайдеру модели вместе с вопросом. Для документов с ограниченным доступом это решение службы ИБ; без внешнего провайдера остаётся локальная модель внутри контура. Подробно: https://drxinfra.ru/blog/rx-ai-assistant-security.html и `docs/security.md` в репозитории rxmcp.
